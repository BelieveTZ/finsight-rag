## 当前 GPU 占用

nvidia-smi 列出了若干图形程序及一个 PID 为 30448 的 Python 计算进程。补充只读查询显示该进程使用应用附带的 Python 路径。

Windows WDDM 模式下工具未提供各进程准确显存用量，因此不能断定单个进程占用了多少显存，也不能仅凭可执行文件路径确定其任务归属。此次没有读取完整命令行、结束进程或修改其配置。

在首次本地推理前，由用户确认正在运行的任务并自行释放必要资源，再重新检查可用显存与内存。显卡有 12 GiB 总容量不代表现在就有相应可用容量。

## 运行环境

- 当前 PowerShell PATH 中没有发现 python、py、uv、ollama 或 docker 命令；常见用户安装目录中也未发现独立 Python、Ollama、LM Studio，不能据此排除自定义位置的安装。
- 可通过绝对路径调用应用附带的 Python 3.12.14。模块存在性检查未发现 torch、transformers、sentence_transformers、llama_cpp 或 psutil。
- PATH 中存在 nvidia-smi 和 wsl；本次未验证 WSL 发行版或 Linux 推理环境，不能认为 WSL 已配置完成。
- 项目重启后没有活动的 .venv。原环境在备份目录，pyvenv.cfg 仍记录迁移前路径；后续应新建项目环境，不将移动过的环境当作可复现安装。
- 常见 Ollama / LM Studio 模型目录未找到；本次未全盘搜索模型。

## 对实施的影响

1. 优先选择原生 Windows 可运行方案。用独立、稳定的 Python 安装和项目环境管理检索依赖，生成模型通过本机推理服务访问；无需将 Docker 或 WSL 设为前置条件。
2. 小型英文嵌入模型与小型重排器可优先使用 CPU、小批次和单请求处理，避免与生成模型争抢显存。具体时延必须实测。
3. 12 GiB 显卡适合优先验证约 8B 参数的四位量化生成模型；从 4K 上下文开始，成功后再考虑 8K。权重体积不等于推理总显存，还需 KV 缓存、运行时及桌面空间。
4. 模型、文档与缓存建议放在空间充足的 E 盘，安装前显式配置缓存目录。可先预留约 15–25 GiB 作为规划余量，实际占用依下载版本与依赖而定。
5. 若现有 GPU 任务持续占用，可先做数据与 CPU 检索实验；CPU 生成只作为小样本试验备选，不能提前承诺整套评测时长。收费 API 替代方案需另有预算授权。

## 验证边界

当前结论是硬件可行性判断，不是模型兼容性或效果验收。本次没有测得 Token/s、回答准确率、模型加载峰值或完整实验耗时。

模型选择的官方来源、估算费用及进一步限制见 [模型方案](MODEL_OPTIONS.md)。后续首个验证应是释放资源后执行一次模型加载、一个非预设问题和一小批开发题，记录峰值显存、耗时及答案，再决定完整实验规模。
